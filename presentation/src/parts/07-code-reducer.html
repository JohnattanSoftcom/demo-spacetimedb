[SpacetimeDB.Reducer]
public static void ClaimVehicle(ReducerContext ctx, uint vehicleId)
{
    var user = RequireRole(ctx, Role.Driver);   // rôle lu en base
    if (ctx.Db.DriverAssignment.VehicleId.Find(vehicleId) is { } taken)
        throw new Exception($"Déjà pris par {taken.DriverName}.");
    ctx.Db.DriverAssignment.Insert(new DriverAssignment {
        VehicleId = vehicleId,
        DriverIdentity = ctx.Sender,     // jamais un paramètre
        DriverName = user.Name,
        ClaimedAt = ctx.Timestamp,
    });
    Audit(ctx, user.Name, "VEHICLE_CLAIMED", ...);
}

ctx.Sender

L’identité vient de la connexion authentifiée, jamais d’un argument.

throw = rollback

Une exception annule tout. L’appelant reçoit le message d’erreur.

Une transaction

L’affectation et l’audit sont écrits ensemble, ou pas du tout.

Un reducer, c'est du code serveur ordinaire. L'identité vient de ctx.Sender, c'est-à-dire de la connexion authentifiée, jamais d'un argument que le client pourrait falsifier. Si on lance une exception, tout est annulé et l'appelant reçoit le message d'erreur. Et tout le reducer est une seule transaction : l'affectation et l'audit sont écrits ensemble, ou pas du tout.
